Voyara - a travel booking app, built end to end

Tours with route maps, a gear shop with a cart, Stripe payments and user accounts - written in TypeScript from the React frontend to the Express API, tested, containerised and deployed through a gated CI/CD pipeline.

The product

What a visitor can do

Find a tour

Filter by location, difficulty, length and price, sort by price or rating. Every tour has a readable address like /tour/the-sea-explorer.

See the route

A Mapbox map numbers each stop by day and draws the driving route between them, with distance and drive time.

Book and pay

Choose a date and guests - a per-guest service fee is added - and pay through Stripe Checkout.

Shop for gear

A cart that works without an account (kept in the browser) and syncs to the account after login.

Manage an account

Sign up, log in, reset a password; bookings, favourites, reviews and settings in one place.

Review honestly

Only travellers who booked a tour can review it. Light and dark themes throughout.

Quality

Tested, and deployed through a gate

About 650 automated tests cover both apps: 214 on the frontend (pages, hooks, Redux slices, the map, checkout flows) and 439 on the backend - every route, auth, rate limits, the error handler, a dedicated NoSQL-injection suite, and integration tests against a real MongoDB. 

 lint (backend) ─┐
 lint (frontend) ┤
 npm audit       ┼─► build ─► deploy API / deploy web
 tests (backend) ┤              (manual button only)
 tests (frontend)┤
 docker build x2 ┘
  • Six independent checks run in parallel on every push and pull request.
  • Deploys are manual and gated: the button re-runs every check and deploys only if all pass. Merging never deploys by itself.
  • Both Docker images are built in CI, so a broken Dockerfile shows up before deploy day.
  • Secrets live only in Fly and GitHub secrets - never in the repository or an image layer.

Decisions

Engineering choices worth discussing

One route, id or slug

GET /tours/:idOrSlug reads a 24-character hex value as a MongoDB id and anything else as a slug - readable page URLs, stable ids for bookings and reviews.

Errors people can act on

Database and token errors become clear 4xx responses. The public sees fixed messages; details go to the logs.

Tests that run anywhere

A fixed time zone, placeholder tokens and a mock API port make CI and a fresh clone behave exactly like the developer's machine.

Lean, safe images

The API is compiled with the full toolchain, then copied into a slim image running as a non-root user; the web app is unprivileged nginx with long-term caching for hashed assets.
